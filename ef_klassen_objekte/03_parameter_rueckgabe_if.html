(03) Parameter, Rückgabewerte und bedingte Anweisungen

Gehört zum Arbeitsblatt AB1 „Wie schütze ich mein Auto vor falscher Benutzung?“. Hier findest du den Ausgangscode, ausführliche Erklärungen und Hilfen.

Ausgangscode der Klasse Auto 
/**
 * Ein Auto mit Farbe, Tempo und Motor.
 * Ausgangscode für Einheit (03): Diese Klasse ist noch unvollständig.
 */
public class Auto
{
    // Attribute
    private String farbe;
    private int tempo;
    private int maxTempo;
    private boolean motorAn;

    /**
     * Konstruktor: Ein neues Auto ist rot, steht still,
     * fährt höchstens 200 km/h und der Motor ist aus.
     */
    public Auto()
    {
        this.farbe = "rot";
        this.tempo = 0;
        this.maxTempo = 200;
        this.motorAn = false;
    }

    /**
     * Gibt die Farbe des Autos zurück.
     */
    public String gibFarbe()
    {
        return this.farbe;
    }

    /**
     * Setzt die Farbe des Autos auf den übergebenen Wert.
     */
    public void setzeFarbe(String pFarbe)
    {
        this.farbe = pFarbe;
    }

    /**
     * Startet den Motor.
     */
    public void starteMotor()
    {
        this.motorAn = true;
    }

    /**
     * Erhöht das Tempo um den übergebenen Wert.
     */
    public void beschleunigeUm(int pTempo)
    {
        this.tempo = this.tempo + pTempo;
    }

    /**
     * Verringert das Tempo um den übergebenen Wert, aber höchstens bis 0.
     */
    public void bremseUm(int pTempo)
    {
        if (this.tempo - pTempo >= 0)
        {
            this.tempo = this.tempo - pTempo;
        }
        else
        {
            this.tempo = 0;
        }
    }
}
Kommentare lesen! Über jeder Methode steht in einem Kommentar /** … */, was sie tut. Lies diese Kommentare, bevor du weiterarbeitest. Einiges kennst du schon: Attribute, Konstruktor und starteMotor(). Die anderen Methoden lernst du in dieser Einheit genauer kennen.

Schritt 3 Methoden mit Rückgabewert: Getter

AB Aufgabe 2

Bisher stand vor jeder Methode void („leer“): Die Methode tut etwas, gibt aber nichts zurück. Eine Methode kann aber auch eine Antwort zurückgeben. Schau dir gibFarbe() an:

    public String gibFarbe()
    {
        return this.farbe;
    }
  • Statt void steht vor dem Namen der Datentyp der Antwort, hier String, weil die Farbe ein Text ist.
  • Mit return gibt die Methode den Wert zurück. Danach ist die Methode beendet.
  • Im Klassendiagramm steht der Datentyp der Antwort hinter der Methode: + gibFarbe() : String.
  • In BlueJ siehst du die Antwort in einem kleinen Fenster, wenn du die Methode aufrufst.

Methoden, die nur den Wert eines Attributs zurückgeben, heißen Getter (von engl. to get, bekommen). Ihr Name beginnt mit gib, bei Wahrheitswerten mit ist.

im KlassendiagrammKopf der Methode in Java
+ gibFarbe() : Stringpublic String gibFarbe()
+ gibTempo() : intpublic int gibTempo()
+ istMotorAn() : booleanpublic boolean istMotorAn()

Deine Aufgabe: Ergänze gibTempo(), gibMaxTempo() und istMotorAn() nach dem Muster von gibFarbe(). Ergänze außerdem stoppeMotor(); das kennst du schon. Übersetze und teste alle neuen Methoden.

⚠️ Fehlermeldung „Rückgabeanweisung fehlt“ (englisch „missing return statement“): In einer Methode mit Rückgabewert fehlt das return. Steht dagegen void vor dem Namen, darf kein Wert zurückgegeben werden.

Teil B: Methoden, denen man etwas mitgibt

Schritt 4 Methoden mit Parametern: Setter

AB Aufgabe 3a

Bisher taten unsere Methoden bei jedem Aufruf immer genau dasselbe. Manche Methoden brauchen aber beim Aufruf einen Wert, z. B. die neue Farbe des Autos. Schau dir setzeFarbe an:

    public void setzeFarbe(String pFarbe)
    {
        this.farbe = pFarbe;
    }
  • In den runden Klammern steht der Parameter: erst sein Datentyp (String), dann sein Name (pFarbe). Den Namen beginnen wir mit p für „Parameter“.
  • Beim Aufruf gibst du in BlueJ den Wert ein, z. B. "blau". Dieser Wert steht dann in pFarbe.
  • this.farbe = pFarbe; speichert den übergebenen Wert im Attribut farbe.
  • Im Klassendiagramm steht der Parameter in der Form name : Datentyp in den Klammern: + setzeFarbe(pFarbe : String).

Methoden, die ein Attribut auf den übergebenen Wert setzen, heißen Setter (von engl. to set, setzen). Ihr Name beginnt mit setze.

Parameter oder Attribut? Der Parameter pFarbe ist nur der Wert, den du beim Aufruf mitgibst. Er existiert nur, solange die Methode läuft. Das Attribut farbe gehört zum Objekt und behält seinen Wert dauerhaft.

Deine Aufgabe: Ergänze den Setter setzeMaxTempo(int pMaxTempo) und teste ihn. Inspiziere das Auto vor und nach dem Aufruf.

Schritt 5 Ein zweiter Konstruktor

AB Aufgabe 3b und 3c

Bisher ist jedes neue Auto rot und fährt höchstens 200 km/h. Schöner wäre es, Farbe und Höchsttempo schon beim Herstellen festzulegen. Dafür bekommt die Klasse einen zweiten Konstruktor mit Parametern:

  • Eine Klasse darf mehrere Konstruktoren haben. Alle heißen genau wie die Klasse und unterscheiden sich nur in ihren Parametern.
  • Mehrere Parameter werden durch Kommas getrennt: Auto(String pFarbe, int pMaxTempo).
  • Auch der neue Konstruktor muss allen Attributen einen Startwert geben. Ein neues Auto steht still (Tempo 0), und der Motor ist aus.

Deine Aufgabe: Ergänze den Konstruktor direkt unter dem ersten. Beim Rechtsklick auf die Klasse bietet BlueJ dir dann zwei Möglichkeiten an, ein Auto herzustellen. Erzeuge mit beiden je ein Auto und inspiziere sie.

Schritt 6 Bedingte Anweisungen mit if und else

AB Aufgabe 4

Oft soll eine Methode etwas nur unter einer Bedingung tun. Dafür gibt es die bedingte Anweisung mit if („wenn“) und else („sonst“):

if (Bedingung)
{
    // wird ausgeführt, wenn die Bedingung wahr (true) ist
}
else
{
    // wird ausgeführt, wenn die Bedingung falsch (false) ist
}
  • Die Bedingung steht in runden Klammern. Sie ist entweder wahr oder falsch.
  • Es wird immer genau einer der beiden Blöcke ausgeführt.
  • Der else-Teil darf auch fehlen. Dann passiert nichts, wenn die Bedingung falsch ist.
  • Hinter if (…) und hinter else steht kein Semikolon.

Bedingungen vergleichen meist zwei Werte:

ZeichenBedeutungBeispiel
< / <=kleiner / kleiner oder gleichthis.tempo < 50
> / >=größer / größer oder gleichthis.tempo - pTempo >= 0
==gleich (zwei Gleichheitszeichen!)this.tempo == 0
!=ungleichthis.tempo != 0

Ein Attribut vom Typ boolean ist selbst schon eine Bedingung: if (this.motorAn) bedeutet „wenn der Motor an ist“.

Ein Beispiel aus dem Ausgangscode: bremseUm verhindert, dass das Tempo negativ wird.

    public void bremseUm(int pTempo)
    {
        if (this.tempo - pTempo >= 0)
        {
            this.tempo = this.tempo - pTempo;
        }
        else
        {
            this.tempo = 0;
        }
    }

Spiele die Methode im Kopf durch: Was passiert bei bremseUm(30), wenn das Auto 50 km/h fährt? Und was, wenn es nur 20 km/h fährt? Prüfe deine Vermutung danach in BlueJ.

Schritt 7 Das Beschleunigen schützen

AB Aufgabe 5

Jetzt schützt ihr beschleunigeUm vor falscher Benutzung. Geht in zwei Teilen vor und plant jeden Teil zuerst auf dem Arbeitsblatt: Welche Bedingung prüft ihr? Was passiert, wenn sie wahr ist, was, wenn sie falsch ist?

a) Nie schneller als das Höchsttempo. Würde das Tempo durch das Beschleunigen größer als maxTempo, wird es genau auf maxTempo gesetzt. Das funktioniert ganz ähnlich wie bremseUm.

Hilfe 1 zu a): Welche Bedingung?

Berechne, wie schnell das Auto nach dem Beschleunigen wäre: this.tempo + pTempo. Vergleiche das mit dem Höchsttempo: Ist es kleiner oder gleich this.maxTempo?

Hilfe 2 zu a): Das Gerüst 
    public void beschleunigeUm(int pTempo)
    {
        if (this.tempo + pTempo <= this.maxTempo)
        {
            // Was passiert, wenn das Höchsttempo nicht überschritten wird?
        }
        else
        {
            // Was passiert sonst?
        }
    }

b) Nur mit laufendem Motor. Das Auto beschleunigt nur, wenn der Motor an ist. Sonst erscheint auf der Konsole ein Hinweis, z. B. „Starte zuerst den Motor!“.

Hilfe zu b): if innerhalb von if

Prüfe zuerst, ob der Motor an ist. Nur in diesem Fall kommt die Prüfung aus a) zum Zug. Ein if darf dafür innerhalb eines anderen if stehen. Man nennt das verschachtelte bedingte Anweisungen. Die ganze Lösung aus a) wandert dabei in den if-Teil der äußeren Prüfung.

        if (this.motorAn)
        {
            // hier steht deine Lösung aus a)
        }
        else
        {
            // Hinweis auf der Konsole ausgeben
        }

Testen: Prüft eure Methode mit diesen Fällen. Startet für jeden Fall ein neues Auto mit dem ersten Konstruktor (Höchsttempo 200).

Schritt 8 Zusammenfassen

Vergleiche deine fertige Klasse mit dem Klassendiagramm aus Schritt 1. Fehlt noch etwas? Überprüfe dich danach mit der Zusammenfassung.

Zusammenfassung anzeigen

Rückgabewert: Eine Methode kann eine Antwort zurückgeben. Statt void steht der Datentyp der Antwort vor dem Namen, mit return wird der Wert zurückgegeben.

Getter: gibt den Wert eines Attributs zurück, z. B. public int gibTempo().

Parameter: ein Wert, den man der Methode beim Aufruf mitgibt. Er steht mit Datentyp und Namen in den runden Klammern.

Setter: setzt ein Attribut auf den übergebenen Wert, z. B. public void setzeMaxTempo(int pMaxTempo).

Mehrere Konstruktoren: heißen alle wie die Klasse und unterscheiden sich in den Parametern.

Bedingte Anweisung: if (Bedingung) { … } else { … } führt genau einen der beiden Blöcke aus. Bedingungen können auch ineinander geschachtelt werden.

Zusatz Für Schnelle: negative Werte

Mit negativen Werten lässt sich das Auto immer noch überlisten: bremseUm(-50) macht es schneller, beschleunigeUm(-30) langsamer, und setzeMaxTempo(-10) ergibt ein unsinniges Höchsttempo.

  1. Schütze bremseUm und beschleunigeUm: Ist pTempo negativ, passiert nichts außer einem Hinweis auf der Konsole.
  2. Schütze setzeMaxTempo: Nur Werte größer als 0 werden übernommen.
💡 Die Bedingung „pTempo ist nicht negativ“ lautet pTempo >= 0. Überlege, an welcher Stelle der Methode diese Prüfung am besten steht.
